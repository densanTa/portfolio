### 01. 業務委託によるアプリケーション機能のチーム開発

**Category:** Professional Development

**Technologies:** Unity / C# / Claude Code / Visual Studio Code

ベンチャー企業での業務委託として、既存アプリケーションのゲーム機能および社内ツールの拡張アドオンを開発しました。

#### 担当業務

- ゲーム機能の企画・設計・実装
- ゲーム内UIの実装
- 社内ツールの拡張アドオンの開発

#### Technical Highlights

**課題：LLMとの対話における不正行為とゲームの公平性**

プレイヤーとLLMが会話を通じて勝敗を競うゲームにおいて、プレイヤーがLLMへの指示を工夫して不正にポイントを獲得したり、LLMの想定外の発言によって勝敗が左右されたりする可能性がありました。

**対策：会話制御と勝敗判定の役割分離**

- 会話を担当するLLMのプロンプトを調整し、不正な指示や想定外の会話への対応を設計
- 会話を担当するLLMとは別に審判AIを用意し、会話の進行と勝敗判定の役割を分離
- ゲームルールの一貫性を維持するためのガードレールを設計
- Structured Outputsを用いた、安定したシステムの設計

#### 成果

ゲームバランスを調整し、最終的にAI側が約4割の勝率となる状態を実現しました。

### 02. 筋トレタイマー・成長管理アプリ（workoutTimer）

**Category:** Personal Development

**Technologies:**

- **Web版：** HTML / CSS / JavaScript
- **Androidネイティブ版：** Dart / Flutter
- **開発支援：** Claude Code / Claude

自身のトレーニングを効率的に管理するため、ワークアウトタイマーと成長記録を一体化したアプリケーションを開発しました。

最初は単一HTMLファイルで簡易版Webアプリを作成し、実際のトレーニングで使用しながら改善を重ね、その後、目的ベースの仕様書を作成してFlutterによるAndroidネイティブ版へ移植しました。

#### Motivation

本格的に筋トレを行う際には、インターバルの計測、重量・回数の記録、過去のトレーニング結果の確認など、複数の作業が発生します。これらをすべて手作業で別々に行うのは非常に面倒で、自動化することでかなりの知的労働を減らすことができるのではと考えました。

そこで、休憩の計時・トレーニング記録・過去データの参照を一つのアプリに統合し、トレーニングに集中しながら成長を確認できる仕組みを目指しました。

#### Key Features

**休憩タイマー**

- セット完了と同時に120秒のインターバルタイマーが自動で開始し、スキップも可能
- 休憩終了を音・バイブレーション・通知で知らせる
- 休憩中に次の種目の過去データを表示し、次のセットに向けた準備を支援

**成長可視化＆成長トラッカー**

- セットごとの重量・回数を記録し、直前の入力値を初期値として表示
- 同じ種目・重量・セット番号の直近の記録を比較対象として表示
- 自己ベスト更新や前回記録の超過を検知して表示
- 重量別の回数推移を折れ線グラフで可視化（半年・1年・全期間）
- 過去の種目を履歴から呼び出し、メニュー作成の手間を削減

#### Technical Highlights

**1. アーキテクチャとデータ管理**

- **Web版：** HTML・CSS・JavaScriptを単一ファイルにまとめた自己完結型の構成。約2,800行のコードで、localStorageによるデータ保存とCSVバックアップを実装
- **Androidネイティブ版：** Providerによる状態管理を採用し、`WorkoutController` に進行ロジックを集約。データベース・CSV・通知・進行状況保存の各機能をサービス層に分離
- **データの互換性：** Web版とネイティブ版でCSVフォーマットを統一し、バージョン間のデータ移行に対応。表示形式と保存形式を分離してデータの整合性を確保

**2. 目的ベースの仕様書によるプラットフォーム移植**

機能の実装方法ではなく「何を実現するための機能なのか」を中心に仕様書を作成しました。

例えば、Web版では無音のビープ音を利用していたスリープ防止の仕組みを、ネイティブ版では終了時刻に基づくローカル通知の予約へ置き換えました。プラットフォームごとの制約に合わせ、目的を維持しながら実装方法を再設計しています。

**3. 技術選定とトレードオフの検討**

Google Driveによるクラウド同期について、OAuth認証・トークン管理・データ競合・iOS対応などの実装コストを検討しました。その結果、現段階の個人開発では負担が大きいと判断し、CSVによるバックアップ・復元を採用しました。

**4. AI開発支援ツールの活用**

- 要件の不足や矛盾をAIが推測で補わず、実装前に質問して明確化するためのClaude Skillを自作
- Web版の仕様を整理したうえで、機能単位に分けてFlutterへ移植
- スクリーンショットからHTMLモックアップを作成し、UIを確認しながら改善
- AIに実装を任せるだけでなく、要件定義・設計判断・動作検証を自ら担当

**5. テストと不具合修正**

- Web版では、変更ごとにNode.jsによる構文チェックとモックテストを実施
- ネイティブ版では、比較対象の決め方・自己ベスト判定・CSV日時形式・グラフ集計などをWeb版の実装と照合し、仕様との不一致を修正
- Android 12以降で、正確なアラームに関する権限不足により通知予約が失敗する不具合を特定し、権限リクエストを追加して解消
- Android実機での動作確認とリリースAPKのビルドを実施

#### Current Status / Future Development

- Androidネイティブ版のリリースAPKをビルド済み
- メニュー変更画面の実装
- 広告機能（スタミナ制・リワード広告）の検討・実装
- Google Playでの公開、iOS対応

### 03. 3D VRアクションゲーム

**Category:** Team Development / Leadership

**Technologies:** Unity / C# / Blender / Suno AI / Git / claude code

大学の部活動において、部長としてメンバーを率い、学園祭での展示を目指した3D VRアクションゲームの制作を推進しました。複数の制作班が連携し、約1か月という限られた期間で作品を完成させました。

#### Role & Responsibilities

- プロジェクトの企画・進行管理
- Unityを用いたゲームシステムの開発
- 3Dモデル・音楽・システム・ゲームデザインなど、各班の連携と意見調整
- メンバーへの役割分担、開発支援、後輩の技術指導

#### Technical Highlights

**1. VRの没入感を意識した操作・物理演算**

- コントローラの操作に対応したパンチや銃の動作を実装
- 物理演算を活用し、殴る・銃を撃つといった動作の現実感を高める設計を採用

**2. 複数班の連携と制作物の一貫性**

3Dモデル・音楽・システム・ゲームデザインの各班が並行して作業するため、週1回のミーティングを設けました。進捗や仕様を共有し、データの競合を防ぐだけでなく、作品全体の世界観やデザインの一貫性を維持するための調整を行いました。

**3. 短期間での開発推進**

約1か月という限られた開発期間に対し、完成から逆算して作業を計画し、メンバーへの役割分担と進捗管理を実施しました。各メンバーの専門性を活かして作業を任せることで、複数の制作工程を並行して進めました。

**4. Gitを用いた共同開発の支援**

Gitの使用経験が少ないメンバーに対し、Pull・Pushなどの基本操作や共同開発の進め方を共有しました。開発中に発生したコンフリクトへの対応も担当し、チームで開発を進められる体制づくりに取り組みました。
